# Installed import check

Run `node <installed-skill-directory>/scripts/check-imports.mjs <file>` from the application workspace. The JSON result distinguishes an incomplete inspection (`measured:false`) from supported imports or definite missing names/subpaths. Never run application code to obtain this evidence. Missing Node, unreadable files, unsupported syntax or missing declarations produce no automatic warning.

The Claude plugin adapter registers the router's `PostToolUse` hook when the skill is invoked. Claude keeps such hooks for the rest of the session, including later turns. Every invocation therefore requires a native Write/Edit event, a file inside the current workspace and a direct named Arkiv SDK import. Unrelated files, unrelated chains and shell commands are excluded. Standalone installs without `CLAUDE_PLUGIN_ROOT` use the explicit script command instead.

Actual Codex writes in the isolated native probe did not execute this frontmatter hook. Explicit execution of the packaged script succeeded and is the tested advisory alternative; it is not an equivalent lifecycle event and supplies no observed skill-use metric. This observation does not establish support in other Codex versions or clients. Comparable context ablation is required before publishing this hook in a distribution.

## Evidence and reproduction

The sanitized ETHRome September 12 friction report, sections 1–3, observed SDK 0.7.0 declaring only `braga`, `kaolin` and `localhost` in its chains entrypoint while current examples required `tiramisu`. It also recorded a different location for `ExpirationTime`. These observations justify checking the actual installed export map and declaration names, rather than assuming that current examples work on an older installation.

Reproduction: `node tests/snippets/published-imports.mjs` obtains official 0.7.0 and 0.8.1 tarballs in an isolated temporary workspace, verifies their published integrity and reads their declarations without installation or package-script execution. A named `tiramisu` import fails on 0.7.0 and passes on 0.8.1. Synthetic positive, negative and neighboring cases in `tests/snippets/import-check.test.mjs` also cover old exports, aliases, comments, strings, unrelated `viem/chains` imports and ambiguous declarations. These are not observations of a live network.

No private-key detector is selected: the retained evidence inspected here did not establish the proposed key-literal failure. A chain/RPC policy is also deferred: the observed retired-chain import is covered by declaration evidence, while arbitrary network configuration requires explicit client binding to avoid flagging unrelated connections. This checker makes no network calls and declares no network compatibility.

Limits: static named imports and explicit non-wildcard package subpath maps only. Conditional root exports and fallback arrays at any nesting level remain unmeasured; an absent literal `.` key in those formats does not establish a missing root export. Unsupported target formats cannot be ignored in favor of a readable sibling target. Unresolved conditions such as `node`, `browser` or custom conditions also remain unmeasured, because inspecting only their default branch could incorrectly report a missing name. Standard import/require declaration targets use TypeScript extension substitution. The SDK's Bun TypeScript entrypoints are read as text, never executed. Explicit `types` targets do not suppress inspection of those other supported branches. A name is reported missing only if absent from all inspected targets; this conservative union does not certify compatibility with a particular resolver. Dynamic imports, CommonJS require expressions, namespace/default imports, unreadable targets, compound variable declarations and unsupported external declaration reexports remain unmeasured. This is not a TypeScript compiler or a secret scanner.

Diagnostics quote the requested subpath and names back to the agent, so the check reports only plain package subpaths (lowercase letters, digits, `.`, `_` and `-` segments, at most 128 characters) and names of at most 64 characters. Any other SDK specifier or name leaves the whole file unmeasured and is never echoed. Each declaration file is read at most once per check, and a check stops after 128 declaration files.

Namespace members and ambient module/global declarations are separate scopes. Those files remain unmeasured because this reader does not resolve scope or declaration merging; their inner exports cannot establish package-level names.

Sources: [Claude hook lifetime](https://code.claude.com/docs/en/hooks#hooks-in-skills-and-agents), [Codex hooks](https://learn.chatgpt.com/docs/hooks), [SDK 0.7.0](https://www.npmjs.com/package/@arkiv-network/sdk/v/0.7.0), [TypeScript namespace scope](https://www.typescriptlang.org/docs/handbook/namespaces.html).
